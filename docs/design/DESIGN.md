# Realm design source

## Purpose

Realm's editing surface stays quiet so the map remains the dominant object. The initial interface is a macOS utility, not a dashboard or a fantasy-themed presentation. Viewing styles may become richer later, but they must remain derived renderers over the same project data.

## Initial states

- Realm enters the editor directly with the 128 by 73 regular-hexagon editing grid fitted inside the available canvas at relative zoom 1. The complete bounded world remains visible with fit padding equal to 10% of the shorter viewport side, clamped from 40 through 160 CSS pixels on every side, and without deforming boundary cells. A narrow or wide viewport may leave additional letterbox space on its secondary axis, but cannot zoom out beyond that full-world view. Resizing recomputes the fit and responsive padding while preserving the relative zoom. The editor does not render separate origin or focus axes. It restores the open world when one exists, otherwise opens the first world in the app-managed library, or creates `無題の世界` when the library is empty.
- The editor provides terrain drawing/thickness, region coloring, erasing, an accessible `グラブ` action, and `シェイピング` in the map tool palette, plus `戻す` and `進む`. Valid terrain, region, grab, and shaping edits save automatically; natural map pan gestures remain available.

Visible controls remain code-native. The radial map palette exposes the terrain drawing/thickness control, region color control, eraser, and an accessible `グラブ` button. There is no startup screen, terrain list, creation form, persistent drawing-range panel, or presentation-settings sidebar. The editor also exposes an openable and closable right-side object manager; it is an auxiliary surface for the currently implemented region objects, not a settings sidebar. Selecting `地形を描く（太さ調整）` activates terrain drawing and opens an accessible 1–5 cell thickness flyout. Selecting `領域` activates freehand enclosure selection and opens ten accessible circular color buttons; the chosen color remains transient until a completed enclosure is saved. The selected color button grows briefly and keeps a visible focus/selection ring, and the choices remain keyboard accessible. The enclosure is only an input guide: its interior hex cells are converted to one or more saved grid-snapped polygons with one persistent region ID, while disconnected parts keep separate shape IDs. Selecting `消しゴム` activates layer deletion and opens its `地形削除` / `領域削除` toggle buttons plus the 1–5 cell thickness control; `地形削除` is the default and clears terrain and region shapes together, while `領域削除` clears only the region shapes. The deletion target definitions remain grouped so future eraser targets can be added without changing the pointer workflow. Selecting `グラブ` treats every shape with the pressed region's persistent ID as one logical mass and persists the full fixed-grid translation without splitting the ID. If the destination overlaps another region, the move is rejected and both regions remain unchanged. Grabbing a visible terrain or region edge previews outward expansion or inward retraction as a grid-snapped polygon update, follows the pointer when it returns, and retains the region ID. The preview hides the stale canonical layer for the grabbed mass and shows exact transient destination cells until the grab is released. World-edge destinations remain invalid. The flyouts remain outside the palette, clamp to the viewport, and close on the documented exclusive, outside, Escape, or blur actions. Terrain drawing, region enclosure, erasing, grab, and object-manager actions retain temporary previews and cancellation guarantees. A primary-button map action used to dismiss the palette is consumed and cannot also edit or pan the map. The renderer reads canonical map shapes; cell IDs remain transient interaction data, and compatibility feature rows remain hidden.

Selecting `シェイピング` activates a click-to-shape interaction: for the clicked logical region, only cells without a `terrain` attribute are cleared, while terrain-backed region cells remain. The clear is saved as one region-attribute operation and can be undone as one step.

## Visual system

- Interface chrome uses true white and cool neutral gray. The default map canvas is true white; persistent terrain is shown by an unfilled outline rather than a colored interior. Optional cartographic themes may color the canvas, but must not turn toolbars and panels into decorative scenery.
- Text is charcoal with a restrained deep blue-green or cool blue selection accent.
- Use the macOS system font stack. Controls use explicit compact typography rather than browser defaults.
- Prefer rails, separators, lists, and the full map canvas over nested cards or floating panels.
- Borders are thin and low contrast. Shadows are limited to controls that must sit over the canvas.
- Keyboard focus remains visible. Terrain outline changes use a brief, non-looping grid-aligned expansion or retraction, and new regions briefly fade into their final style, while `prefers-reduced-motion` applies completed presentation immediately.

## Layout contract

The editor uses one native overlay title bar with `戻す`, `進む`, and an object-manager toggle, a dominant OpenLayers canvas, a closable right-side object manager, and a contextual map palette. No primary rail, terrain sidebar, floating map buttons, or bottom zoom bar is shown. Do not draw a second set of macOS traffic lights in React. Default zoom and center are part of the map adapter contract and must not be persisted as project data.

The move tool pans the viewpoint with a primary-button drag. A middle-button drag pans in every tool without changing the active tool, and Space plus a primary-button drag provides the same temporary navigation path. Viewpoint movement remains constrained to the fixed editing world so the grid cannot be dragged aside to expose empty canvas. Wheel rotation zooms the canvas.

The canvas cursor reflects the active operation: `grab` for move/navigation and the explicit terrain or region boundary-grab tool, a crosshair for terrain or region drawing, and a small eraser cursor for layer removal. An explicitly disabled canvas uses `not-allowed`; OpenLayers' `grab`/`grabbing` feedback remains the highest-priority state while a pan drag is active.

Terrain drawing and region enclosure modes reserve the primary pointer for their own painting gestures, so a boundary cell can be painted like any other cell. The explicit `グラブ` tool shows dashed handles only on terrain or region boundary cells; dragging one handle outward or inward changes the edge, while pressing an interior region cell moves the whole logical region.

## Allowed editor copy

The editor uses `戻す`, `進む`, and the object-manager toggle in the top row; `地形を描く（太さ調整）`, `領域`, and `消しゴム` with their transient settings are available from the map palette. The right-side object manager lists logical regions and their disconnected polygon parts. It can select a region, set an existing region as the destination for a new chunk, merge selected regions, and separate one part into a new region; each mutation replaces canonical map shapes in one undo step. Startup, library, import, file actions, export controls, world-name editing, zoom buttons, terrain lists, creation metadata, persistent drawing configuration, presentation settings, unavailable layers, and asset management are not shown. There is no separate move button; natural map pan gestures remain available.

## Renderer boundary

React owns transient interface state, including the active tool, region color, viewport, draw-paint range, current paint selection, object-manager open state, selected logical regions, selected region component, and expanded object-manager rows. OpenLayers objects, derived hex polygons, and theme definitions live behind the map adapter and never become storage. The selected theme identifier, grid visibility, export scale, and export extent are bounded project settings that survive reopening.

Canonical `map_shapes` polygons containing terrain and region identity/color are passed to the semantic polygon renderer. A separate bounded renderer draws the fixed editing grid, while transient cell polygons and center markers support selection and hit testing without creating persistent cell geometry. Persisted terrain has no fill and is rendered as an exact grid-snapped outline; shared edges are already removed when the polygon is assembled. Region rendering uses the saved polygon parts and groups them by persistent region ID and color, independent of the terrain layer. During a grab, the stale canonical layer for the grabbed mass is hidden and exact transient destination cells provide the preview; other region features remain visible. Compatibility features remain hidden. Grid-aligned transitions, fade-in, and reduced-motion behavior remain renderer-only, never enter saved data or undo history, and resolve immediately when reduced motion is requested. World-edge terrain and region shapes remain within the bounded world, and the map view fits that extent with responsive padding.

## App icon assets

The transparent PNG master is the source for the bundled app icon used by Electron Forge. The white rounded tile and contour mark remain opaque, while every outer corner must be transparent. The other PNG sizes and `icon.icns` are generated from that master; package inspection verifies the bundled icon and metadata without launching the app.
