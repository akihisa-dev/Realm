# Test strategy

Tests must prove behavior without requiring a real user map or a network. Use temporary directories and in-memory or temporary SQLite databases. Keep fixtures synthetic and free of personal locations.

| Layer | Main evidence |
| --- | --- |
| Pure domain/model | world-name validation, geometry-class validation, cell ID/value validation, and stable identifiers |
| SQLite integration | terrain-cell writes, persistent region-ID writes and round trips, joint terrain-and-region erasure and undo, compatibility-feature round trips, strict write-geometry bounds, bounded palette/grid/canvas project settings, atomic terrain-cell batches, preservation of legacy assets and non-terrain cell layers, v3 through v9 migration to the current schema including legacy region-ID assignment, schema invariants, transactions, rollback, session undo/redo, legacy-format rejection without source mutation, and library reopen through Node `node:sqlite` |
| Electron IPC boundary | app-data library isolation, UUID/path restrictions, read-only transfer preflight, atomic export, artifact size/extension bounds, typed errors, sender/origin allow-lists, coarse IPC permissions, IPC registration before renderer load, and authenticated smoke readiness |
| React/UI | direct editor launch with existing-world open or empty-library creation, absence of the startup/import surface, map palette placement, accessible terrain range, region color, eraser and its terrain/region deletion toggles, and grab controls, four-direction non-overlapping palette anchoring, setting changes without map click-through, top-row `戻す`/`進む`, absence of file/export/world-name/zoom/sidebar controls, discrete hex-cell terrain paint/terrain-and-region erase/region erase and region-enclosure gestures, persistent region-ID propagation, whole-ID movement including visually separated components, region persistence without terrain masking, overlap clipping that preserves the stationary region, terrain and region edge expansion/retraction through the shared cell callback, optimistic save/failure recovery, radial-palette outside-action dismissal without map click-through, project-identity selection reset, preservation and exclusion of inactive compatibility rows, stale request rejection, and undo/redo state |
| OpenLayers adapter | odd-row-offset centers, closed six-sided interior cells, complete-world fit at relative zoom 1, fit recomputation on resize, terrain draw/terrain-erase/region-erase footprints and freehand region enclosure with visible transient previews, region-ID grouping with separate visual components including cells without terrain, whole-ID grab translation and overhang preview, selective smooth-mass hiding with non-target regions retained, overlap previews that omit occupied destinations, terrain and region edge expansion/retraction previews that follow a reversed pull, all-region component rendering without terrain masking or stale preview overlap, world-edge rejection, Escape/pointercancel/blur/lost-capture cancellation, conversion of an enclosure interior to stable cell identifiers, smooth deterministic terrain rings with exact fallback, region-ID shell/hole fills without internal seams, unfilled terrain-mass outlines with shared edges removed, mutually exclusive grid-aligned transition and smooth completed terrain layers, completed paint without a filled-cell residue, grid-aligned expansion and retraction after terrain edits, added and recolored region-cell fade-in with immediate reduced-motion rendering, faint outside grid plus terrain-center markers, transient selection styles, inactive compatibility feature exclusion, pointer-exit/external-release/lost-capture/blur cancellation, wheel zoom, always-available middle-button drag pan, bounded configured raster export and state restoration, listener cleanup, and idempotent disposal |
| Repository | Markdown links, `git diff --check`, secret guard staged/add/modify/type-change/merge-resolution and existing/new-ref range matrix with safe deletion coverage, commit-by-commit version policy |
| Electron runtime smoke | explicitly authorized development launch with fresh temporary `userData`, JSON evidence for main-window creation, renderer load, preload API, and empty library, followed by automatic shutdown |
| macOS package | release-only static arm64 bundle, metadata, DMG, checksum, and non-launching package-smoke inspection; never launch the packaged app for testing |

Before a local push, run strict TypeScript, Vitest/Node tests, renderer and architecture checks, and the scripts declared by the current app package, followed by the repository guards. Before a release tag, also build and statically inspect the Electron Forge arm64 package using the exact local release command documented by the app package.

Tests that require Realm to be running must be separately named, explicitly authorized for the current task, and performed through `Realmをテスト起動.command` or `script/build_and_run.sh`. Never launch a built, packaged, or installed `.app` for testing. GUI tests must not be silently included in the normal unit-test command.
