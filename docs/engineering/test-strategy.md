# Test strategy

Tests must prove behavior without requiring a real user map or a network. Use temporary directories and in-memory or temporary SQLite databases. Keep fixtures synthetic and free of personal locations.

| Layer | Main evidence |
| --- | --- |
| Pure domain/model | world-name validation, geometry-class validation, cell ID/value validation, and stable identifiers |
| SQLite integration | grid-snapped `map_shapes` writes and round trips, stable shape IDs and persistent region IDs, joint terrain-and-region erasure and undo, compatibility-feature round trips, strict polygon/grid bounds, bounded palette/grid/canvas project settings, atomic shape replacement, preservation of legacy assets, schema invariants, transactions, rollback, session undo/redo, v3 through v10 rejection without source mutation, and library reopen through Node `node:sqlite` |
| Electron IPC boundary | app-data library isolation, UUID/path restrictions, read-only transfer preflight, atomic export, artifact size/extension bounds, typed errors, sender/origin allow-lists, coarse IPC permissions, IPC registration before renderer load, and authenticated smoke readiness |
| React/UI | direct editor launch with existing-world open or empty-library creation, absence of the startup/import surface, persistent left-sidebar map palette placement, icon-only controls with accessible labels/tooltips, accessible terrain range, region color, eraser and its terrain/region deletion toggles, grab and shaping controls, renderer preview toggle with read-only state and return path, setting changes without map click-through, right-click not opening a palette, top-row undo/redo/object controls, absence of file/export/world-name/zoom controls, transient hex-cell painting and region-enclosure gestures that commit one grid-snapped Polygon replacement, persistent shape/region-ID propagation, whole-ID movement including visually separated parts, shaping of non-terrain region parts with terrain parts retained, region persistence without terrain masking, overlap rejection that preserves both regions, exact Polygon edge/vertex preview with one pointerup save, optimistic save/failure recovery, sidebar flyout outside-action dismissal without map click-through, project-identity selection reset, preservation and exclusion of inactive compatibility rows, stale request rejection, and undo/redo state |
| OpenLayers adapter | odd-row-offset centers, closed six-sided interior cells, grid-fill at relative zoom 1 for the 4:3 viewport, fill recomputation on resize, direct canonical terrain/region Polygon rendering in edit mode, renderer-only smoothed terrain/region preview, read-only interaction gating with pan/zoom retained, terrain draw/terrain-erase/region-erase footprints and freehand region enclosure with visible transient previews, region-ID grouping with separate Polygon parts including cells without terrain, shaping clicks that clear only non-terrain region parts, whole-ID grab translation and continuous edge/vertex preview, selective canonical-layer visibility with non-target regions retained, overlap rejection, grid normalization at commit, world-edge rejection, Escape/pointercancel/blur/lost-capture cancellation, conversion of an enclosure interior to stable transient cell identifiers, deterministic grid-snapped rings, region-ID shell/hole fills without internal seams, unfilled terrain-mass outlines, transient selection styles, inactive compatibility feature exclusion, pointer-exit/external-release/lost-capture/blur cancellation, wheel zoom, always-available middle- and right-button drag pan, right-button context-menu suppression, bounded configured raster export and state restoration, listener cleanup, and idempotent disposal |
| Boundary pull affordance | exact canonical Polygon hit testing with vertex-over-edge-over-interior priority, edge and vertex preview without IPC on pointermove, one normalized commit on pointerup, inner-hole edge discovery, terrain and region painting remaining active outside grab mode, and explicit-grab palette dismissal before the first map gesture |
| Repository | Markdown links, `git diff --check`, secret guard staged/add/modify/type-change/merge-resolution and existing/new-ref range matrix with safe deletion coverage, commit-by-commit version policy |
| Electron runtime smoke | explicitly authorized development launch with fresh temporary `userData`, JSON evidence for main-window creation, renderer load, preload API, and empty library, followed by automatic shutdown |
| macOS package | release-only static arm64 bundle, metadata, DMG, checksum, and non-launching package-smoke inspection; never launch the packaged app for testing |

Before a local push, run strict TypeScript, Vitest/Node tests, renderer and architecture checks, and the scripts declared by the current app package, followed by the repository guards. Before a release tag, also build and statically inspect the Electron Forge arm64 package using the exact local release command documented by the app package.

Tests that require Realm to be running must be separately named, explicitly authorized for the current task, and performed through `Realmをテスト起動.command` or `script/build_and_run.sh`. Never launch a built, packaged, or installed `.app` for testing. GUI tests must not be silently included in the normal unit-test command.
